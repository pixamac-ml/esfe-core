3. ANALYSE — DUPLICATIONS, INCOMPLÉTUDES, MANQUES
================================================================================

3.1 Duplications détectées
----------------------------
  a) Deux familles de barres/cartes indicateurs :
       - widget_card / metric_card / stat_card / mini_stat / kpi_row
       Tous affichent des chiffres clés. Leur interface varie légèrement.
       Recommandation : unifier autour d'un AcademicStatCard paramétrable.

  b) Sidebars et topbars spécifiques par rôle :
       - secretary_sidebar / supervisor_sidebar / teacher_sidebar
       - secretary_topbar / supervisor_topbar / teacher_topbar
       Mêmes patterns (logo, navigation, profil, notifications). Une base
       unique AcademicSidebar / AcademicTopbar pourrait les factoriser.

  c) Section headers répétés en dur dans plusieurs dashboards (teacher,
     student, secretary). Recommandation : utiliser systematiquement
     AcademicSectionHeader / page_header.

  d) Onglets : tabs (générique) + step_indicator / stepper (admission).
       Recommandation : AcademicTabs pour les dashboards, AcademicStepper
       pour les workflows linéaires.

3.2 Composants incomplets ou peu réutilisables
-----------------------------------------------
  a) chart_card : dépend d'une librairie non unifiée (Chart.js déclaré mais
     graphes potentiellement variés). Pas de contrat de données clair.

  b) data_table : fonctionnel mais complexe (édition inline, tri, sélection).
     Manque de documentation d'utilisation dans la galerie.

  c) combobox / date_picker / upload_zone : basés sur Alpine ; nécessitent
     une validation manuelle cross-navigateur.

  d) Teacher/student dashboards contiennent beaucoup de HTML inline et de
     JavaScript embarqué dans les templates. Cela réduit la réutilisabilité.

7. IMPLÉMENTATION RÉALISÉE
================================================================================

7.1 Principes respectés
-----------------------
  - Aucune modification de backend, modèles ou vues métier.
  - Aucun composant existant supprimé ni modifié.
  - Utilisation exclusive des tokens CSS (var(--school-primary), var(--success),
    var(--warning), var(--danger), var(--info), var(--text), var(--muted), etc.).
  - Icônes Lucide uniquement (data-lucide).
  - Composants HTMX-ready (hx-get/hx-post/hx-target/hx-swap) et Alpine-ready.
  - Enregistrement automatique via @component.register("academic_*").
  - Import public centralisé dans ui/components/__init__.py.

7.2 Composants créés — intégralité de la liste devin.txt
---------------------------------------------------------
Tous sous ui/components/academic/ et ui/templates/academic/ :

  - academic_card           : conteneur de contenu académique (title, subtitle, icon, slot)
  - academic_stat_card      : indicateur chiffre clé + icône + tendance + lien
  - academic_alert          : message alerte (info/success/warning/danger/primary)
  - academic_table          : tableau de données scolaire (wrapper data_table)
  - academic_filter_bar     : barre de filtres HTMX
  - academic_toolbar        : barre d'outils (titre, compteur, actions)
  - academic_drawer         : panneau latéral HTMX (droite/gauche)
  - academic_modal          : fenêtre modale Alpine.js
  - academic_timeline       : fil chronologique scolaire
  - academic_calendar       : calendrier / emploi du temps (wrapper schedule)
  - academic_quick_action   : bouton d'action rapide HTMX-ready
  - academic_badge          : pastille statut/niveau/rôle (dot ou label)
  - academic_progress       : barre de progression avec tone et taille
  - academic_stepper        : stepper horizontal/vertical
  - academic_empty_state    : écran vide centré avec icône + action slot
  - academic_section_header : titre de section + badge + action slot
  - academic_tabs           : onglets avec support HTMX
  - academic_page_header    : en-tête de page avec breadcrumb + actions
  - academic_page_layout    : gabarit de page (header + grille + slots)
