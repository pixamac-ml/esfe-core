F. PERFORMANCE
================================================================

Mesures/protections implementee :

- la route /dg/ utilise build_dg_shell_context, pas
  build_dg_dashboard_context. Le premier HTML affiche le loading UI Core sans
  recalculer Finance, RH, Planning, Analytics et Annexes avant le GET HTMX de
  la section.

- _build_branch_summaries passe de requetes repetees par annexe/KPI a sept
  agregations groupees fixes pour les donnees de synthese. Les listes
  detaillees (classes, programmes, paiements) ne sont chargees que pour le
  drawer d'une annexe.

- _build_analytics ne compte plus les paiements en attente dans une requete par
  annexe : une aggregation groupee est utilisee.

- le test test_branch_summary_uses_a_fixed_query_budget valide un maximum de
  sept requetes pour deux annexes ; ce budget ne croitra pas avec le nombre
  d'annexes pour les KPI de base.

Limite connue :

Les sections DG chargees restent encore construites depuis le contexte DG
historique large. Leur decoupage domaine par domaine reste prevu pour les lots
ulterieurs, sans lancer de refonte prematuree pendant Lot 0.
