# MISSION — RECENTRAGE DÉFINITIF DU DASHBOARD INFORMATICIEN

Nous devons maintenant revoir le dashboard **Informaticien d’annexe** de ESFé Core.

Cette tâche n’est PAS une reconstruction générale du dashboard et ne doit surtout pas casser les fonctionnalités déjà stabilisées, notamment :

* le module de saisie des notes ;
* la grille de notes ;
* les calculs automatiques déjà réalisés ;
* l’import/export Excel des notes ;
* le module de cartes déjà fonctionnel ;
* les composants UI déjà stabilisés ;
* la navigation HTMX/Alpine existante lorsqu’elle reste pertinente.

Le but est principalement de **corriger le périmètre métier de l’Informaticien** en supprimant ou transférant les responsabilités qui ne lui appartiennent finalement pas.

---

# 1. CONTEXTE MÉTIER IMPORTANT

Après clarification avec l’établissement, nous devons appliquer une séparation stricte des responsabilités.

## Directeur des Études

Le Directeur des Études est le **responsable académique**.

C’est lui qui doit notamment :

* concevoir les maquettes académiques ;
* créer/configurer les structures pédagogiques ;
* définir les UE ;
* définir les EC/matières ;
* affecter les EC aux UE ;
* définir crédits ;
* coefficients ;
* seuils de validation ;
* règles académiques configurables ;
* préparer les maquettes utilisées pour chaque classe ;
* paramétrer les informations académiques nécessaires ;
* contrôler les résultats ;
* valider les résultats ;
* autoriser leur publication.

Ces responsabilités doivent donc progressivement sortir du dashboard Informaticien et appartenir au dashboard Directeur des Études.

Une prochaine tâche sera consacrée au dashboard Directeur des Études.

NE PAS implémenter toute cette nouvelle interface DE pendant cette mission sauf si une petite adaptation technique est indispensable pour éviter une régression.

---

# 2. NOUVEAU RÔLE DE L’INFORMATICIEN

L’Informaticien n’est PAS le créateur de la structure académique.

Il est principalement un **opérateur technique d’annexe**.

Son dashboard doit être beaucoup plus simple et ciblé.

Ses grandes responsabilités sont désormais :

## A. NOTES

L’Informaticien saisit les notes.

Il travaille sur une maquette qui a déjà été préparée/configurée par le Directeur des Études.

Workflow attendu :

Directeur des Études
→ prépare la maquette
→ définit UE/EC/crédits/coefficient/seuils/etc.

Informaticien
→ sélectionne la classe
→ sélectionne le semestre/session concerné
→ ouvre la maquette déjà prête
→ saisit les notes ou importe les notes
→ le système calcule automatiquement
→ vérifie les éventuelles anomalies techniques
→ termine la saisie

Système
→ calcule automatiquement les résultats

Directeur des Études
→ reçoit une notification / état prêt à contrôler
→ vérifie
→ valide
→ publie selon le workflow académique.

### IMPORTANT

L’Informaticien ne doit plus pouvoir :

* créer une UE ;
* créer un EC depuis son workflow de notes ;
* modifier la composition pédagogique d’une maquette ;
* modifier les crédits ;
* modifier les coefficients ;
* modifier les seuils ;
* modifier les règles de validation ;
* construire la structure académique à la place du DE.

La grille de notes existante ne doit toutefois PAS être reconstruite inutilement.

Elle fonctionne déjà et a fait l’objet de nombreuses corrections.

Faire seulement les adaptations métier nécessaires.

---

# 3. IMPORT / EXPORT

Cette fonctionnalité reste chez l’Informaticien.

Il doit pouvoir :

* télécharger/utiliser la maquette Excel autorisée ;
* importer les notes ;
* prévisualiser l’import ;
* détecter les erreurs ;
* corriger les problèmes de données autorisés ;
* exporter les notes ;
* exporter les états nécessaires.

Mais l’import doit fonctionner sur une **structure académique déjà existante**.

Un fichier Excel ne doit pas permettre à l’Informaticien de créer silencieusement :

* UE ;
* EC ;
* crédits ;
* coefficients ;
* règles académiques.

Si la maquette académique n’est pas prête ou présente une incohérence structurelle, l’Informaticien doit recevoir une information claire du type :

> « Cette maquette doit être complétée par le Directeur des Études avant la saisie des notes. »

Ne pas lui proposer un bouton permettant de corriger lui-même la structure académique.

# 6. FICHE TECHNIQUE D’UN UTILISATEUR

Nous voulons améliorer la consultation technique d’un compte.

* date de dernière réinitialisation si disponible ;
* incidents éventuels liés au compte.

## Historique des connexions

L’Informaticien doit pouvoir consulter un historique technique avec idéalement :

* date ;
* heure ;
* adresse IP ;
* navigateur ;
* système d’exploitation ;
* type d’appareil ;

* localisation approximative lorsqu’elle peut être déterminée proprement.

IMPORTANT :

Ne jamais inventer de données.

Si ESFé Core n’enregistre pas actuellement user-agent/IP/login history, auditer d’abord le système existant avant d’ajouter un mécanisme.

Une véritable localisation GPS précise nécessite normalement une autorisation du navigateur et ne doit pas être simulée.

Une géolocalisation approximative dérivée d’une IP peut être envisagée séparément.

Tout mécanisme ajouté doit respecter les exigences de sécurité et de confidentialité du système.

# RÉSULTAT MÉTIER RECHERCHÉ

À la fin de cette tâche, le dashboard Informaticien ne doit plus donner l’impression qu’il dirige le système académique.

Il doit représenter très clairement le métier réel :

> **L’Informaticien d’annexe exploite techniquement le système. Il saisit/import/exporte les notes sur des maquettes préparées par le Directeur des Études, gère les problèmes techniques des comptes, produit les cartes et dispose d’un journal de traçabilité. Il ne définit ni la structure pédagogique ni les règles académiques de l’établissement.**

Le dashboard doit donc être :

* plus léger ;
* plus compréhensible ;
* moins chargé ;
* plus sécurisé ;
* plus rapide à utiliser ;
* cohérent avec la séparation réelle des responsabilités dans l’école.

Commence par AUDITER l’existant avant de modifier quoi que ce soit, puis effectue les changements progressivement en protégeant les fonctionnalités déjà stabilisées.
