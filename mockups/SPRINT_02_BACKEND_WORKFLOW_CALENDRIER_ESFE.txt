SPRINT 2 — BACKEND WORKFLOW CALENDRIER ACADEMIQUE Projet : ESFE Core
Destinataire : Codex

OBJECTIF Construire le backend fonctionnel du Calendrier Académique en
s’appuyant sur les modèles du Sprint 1.

PREREQUIS Le Sprint 1 doit être terminé et les migrations doivent être
vertes.

TACHE 1 Créer les vues backend CRUD du Calendrier Académique. - Liste -
Détail - Création - Modification - Publication - Archivage

TACHE 2 Créer les URLs dédiées.

TACHE 3 Intégrer les permissions : - Directeur des Études : son annexe
uniquement. - DG : toutes les annexes. - Super Admin : accès total.

TACHE 4 Implémenter le workflow :

Brouillon → Validation → Publication → Archivage

Une seule version publiée par année et annexe.

TACHE 5 Créer les règles métier : - empêcher la publication si des
périodes se chevauchent. - empêcher les dates hors année académique. -
empêcher les incohérences de portée (classe, programme, semestre).

TACHE 6 Préparer l’intégration avec AcademicScheduleEvent : - vérifier
les périodes bloquantes avant création d’un cours. - ne pas modifier le
moteur d’emploi du temps.

TACHE 7 Tests : - CRUD - permissions - publication - archivage -
conflits - filtres par annexe et année

LIVRABLE 1. Résumé 2. Fichiers créés/modifiés 3. Tests 4. API/vues
disponibles 5. Points pour Sprint 3

IMPORTANT Aucun frontend. Aucun template. Aucun composant HTMX.
